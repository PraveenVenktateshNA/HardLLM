HardLLM · Step 2 progress

How 60,000 private patient records chose 36,201 public training rows

The hospital's patient data never leaves the hospital. It only votes on which kinds of public text look like it. Those votes are blurred with random noise so no single patient can be traced, and the blurred votes decide what public text gets picked.

The process

From patient records to a public training set

Inside the hospital · private
60,000patient messages

Private patient records

Real questions patients sent, like “I fell yesterday and my ribs hurt badly.” This text never leaves.

300,000votes

Each patient votes for 5 topics

The public data was sorted into 2,208 topics in Step 1 (chest pain, back pain, product reviews, sports news…). Each record names the 5 topics it looks most like. 60,000 × 5 = 300,000 votes.

812of 2,208 topics

Votes are counted per topic

Only 812 topics got any votes. 73 topics got over 1,000 votes each and hold 89% of all votes. The other 1,396 topics (reviews, news, legal, finance) got none.

±15noise per topic

Random noise is added to every topic's count

So nobody can tell whether any one patient is in the data. Privacy level ε = 0.5, which is strong. A count of 7,159 becomes about 7,171. A count of 0 might become 12.

Only these 2,208 blurred numbers leave the hospital. No text, no names.
Outside · public, safe to share
188topics kept

Counts too small to trust are dropped

A topic needs a blurred count of at least 45 (three times the noise) to count. This removes topics that only “got votes” because of the noise.

36,201public rows

Public rows are picked from each kept topic

Each topic gives as many rows as its count asks for. 115 popular topics asked for more rows than they have, so all of their rows were taken (27,769 rows). 73 smaller topics gave a random sample (8,432 rows).

What we fixed and found

Where the paper's version went wrong

  • The paper's code never added the privacy noise.A bug threw the noisy counts away and read a file that was never written. We apply the noise for real.
  • The paper used about 2.6× too little noise.It assumed each patient votes once (they vote 5 times) and allowed the protection to fail for 1 in 100 patients. We use 1 in 60,000.
  • The paper's “smart” row picking is effectively random.Its weights differ by only 0.24% within a topic, and it took about 5 hours. Same result now in seconds.
  • The whole step runs in minutes on a laptop.Matching all 60,000 records to topics took 3.6 minutes. The paper's retrieval model would take about 7 hours for the same matching.
Limits

What this does not show yet

  • The private and public patient questions come from the same website.We split one dataset into a private half and a public half, so close matches were guaranteed to exist. A real hospital's notes would match less well. Testing with data from a different source is planned.
  • Rare conditions get dropped.A condition only a handful of patients have is exactly where one patient stands out, so the noise has to hide it. This is the cost of privacy.
  • One release only.We tried four privacy levels to choose one. A real deployment releases once, at ε = 0.5.
